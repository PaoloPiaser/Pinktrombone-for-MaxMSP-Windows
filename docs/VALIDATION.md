# Validation

Validated on 14 September 2026.

## Shared DSP and adapter

- `dsp/PinkTromboneDSP.cpp` and `.hpp` are byte-identical to the released
  SuperCollider port's MIT standalone engine. The preceding port's published
  TypeScript oracle and server validation apply to that unchanged engine.
- 30 adapter schedules: 44.1, 48 and 96 kHz; Max vector sizes 1, 16, 64, 257 and
  512; model block sizes 1 and 512. All 148 output channels match direct engine
  calls exactly, using double-precision arithmetic.
- Schedules include live frequency/excitation, external aspiration/frication
  noise, constriction gates, independent turbulence, oral/nasal cell targets,
  reset edges, transient edges, and float updates between vectors.
- All 483 live control names at maximum point capacity can be signal-routed.
  Tests cover defaults, finite bounds, nonfinite fallback, connected-signal
  precedence, float restoration on disconnection, and invalid inlet layouts.
- Consecutive one-sample-vector message triggers, rate-change pulse cleanup, and
  preserving signal routing after a rejected configuration pass regression tests.
- Reset messages and transient message pulses pass, including a pulse crossing
  a one-sample vector boundary.
- The test allocation counter detects no heap allocation in audio processing.
  DSP graph setup allocates the engine; float/message handlers use atomics to
  communicate with the audio thread. No mutex or file access is used in perform.
- Native arm64 tests and the x86_64 executable under Rosetta pass. Native
  UndefinedBehaviorSanitizer tests also pass.

## Max host

The universal bundle loads in standalone Max 9.1.4 on Apple Silicon. The
standard 27-inlet/four-outlet instance, a custom three-inlet instance with a
connected frequency signal, and the 148-outlet diagnostic instance have been
instantiated together. A silent-to-speakers recording patch captures 12 selected
outputs. See `max-host-test.json` for the final recording measurements and host
version. The host test is generated by `scripts/make_patches.py` in
`build/externals/host-smoke.maxpat`; it requires DSP already running, opens its
recording after graph setup and records about two seconds without a DAC object.

Float frequency (175 Hz), a float in the fifth/velum inlet (0.4), and a named
tenseness message (0.85) are exercised alongside a connected 220 Hz frequency
signal. Measured glottal pitches are approximately 173.9 and 219.2 Hz; the
upstream simplex/vibrato modulation remains active. The mouth-plus-nose sum
matches the mixed output within one PCM16 quantization unit. Three geometry
outputs match the known cell values within two quantization units.

The local sfrecord~ WAV header reports 44.1 kHz while adstatus sr reports an
actual 48 kHz DSP rate; delaying file creation did not resolve that recorder
metadata discrepancy. The pitch check explicitly uses the observed 48 kHz
DSP rate. This recording is a test artifact and is not distributed as an audio
demo. The 64-bit DSP/adapter parity checks are independent of that recorder.

Native Max host testing is on Apple Silicon. Rosetta tests verify the compiled
Intel engine/adapter code, not an Intel Max session or a physical Intel Mac.
Max 8.2 is the targeted API minimum, not a separately tested host version.

## Distribution and limits

Both binary architectures are present. The complete bundle passes strict
all-architecture ad-hoc signature verification. This does not establish
Developer ID identity or Apple notarization, or guarantee Gatekeeper acceptance
of a quarantined download on another Mac.

The standalone test is an engine/adapter check, not a substitute for Max host
loading; the host recording covers actual bundle loading and signal output.
The tests do not prove every possible audio-driver, polyphony, CPU overload,
invalid geometry, or live performance scenario. The original fixed tract
geometry and timing behavior are retained as documented in PARAMETERS.md.
